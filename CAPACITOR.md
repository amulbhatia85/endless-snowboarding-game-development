# Capacitor Readiness (Phase 10C)

> **Update:** both native platforms have since been added — see `android/`
> (BUILD_APK.md) and `ios/` (BUILD_IOS.md). The analysis below is the
> historical Phase 10C readiness record.

This document records what is already WebView-safe in the current web build and
which Android/iOS configuration steps remain for a future native shell.

## 1. Already WebView-safe in the code

| Area | Status | Notes |
| --- | --- | --- |
| No `window`-only assumptions in the engine | ✅ | `src/game/engine.ts` patches `window`/`document`/`localStorage` via globals that the Node test harness supplies; all rendering goes through the injected `CanvasRenderingContext2D`. Audio and ads are consumed through injected services, not `window.*` directly. |
| Asset paths | ✅ | No `public/` media at all — all sprites, ground patterns and sound are generated procedurally (canvas patterns + WebAudio synthesis), so there are no asset URLs to rewrite for `cap://` schemes. Vite build output is base-relative. |
| Ad layer split | ✅ | `src/game/ads.ts` ships the AdMob **test** unit ids by default with production placeholders (`AD_CONFIG.web.test` / `.production`); the Web/AdSense path and the Capacitor/AdMob path are behind one interface (`initialize`, `showRewarded`, `setLifecycleHandler`). |
| Audio lifecycle | ✅ | `src/game/audio.ts` unlocks on the first user gesture (pointerdown/keydown/touchstart), suspends on `visibilitychange` hidden, resumes on visible; ad lifecycle suspends/restores music. No duplicate resume (unlock is idempotent via `audio.ready`). |
| Viewport / safe areas | ✅ | `index.html` sets `viewport-fit=cover`; HUD spacing is CSS-based, controls are sized ≥44 px hit targets via CSS. |
| Frame timing | ✅ | Engine clamps frame delta to 100 ms and sub-steps physics at ≤25 ms, so Android frame pacing jitters cannot produce physics jumps. |
| localStorage persistence | ✅ | Level progress/settings go through `localStorage` with a versioned, backward-compatible schema (`LEVEL_SAVE_KEY`); a corrupt or missing key falls back to defaults instead of throwing. |

## 2. Dependencies already declared

`package.json` already contains (Capacitor v8 line):

- `@capacitor/core`, `@capacitor/cli` (dev)
- `@capacitor/android`, `@capacitor/app`
- `@capacitor/haptics`
- `@capacitor-community/admob`

They are installed but inert until a platform is added.

## 3. Required Android configuration (when the shell is added)

1. `npx cap init "Afterglow" com.example.afterglow --web-dir=dist`
2. `npm run build && npx cap add android && npx cap sync`
3. `android/app/src/main/AndroidManifest.xml`:
   - `INTERNET` (ads), `ACCESS_NETWORK_STATE` (AdMob),
   - `com.google.android.gms.ads.APPLICATION_ID` meta-data with AdMob's
     real app id before any production release.
4. `android/app/capacitor.build.gradle`: plugin entries for
   `@capacitor-community/admob` are generated by `cap sync`.
5. ProGuard keep rules: AdMob/Capacitor annotations ship with the plugins'
   consumer rules — no manual rules expected.
6. `android/variables.gradle`: `compileSdkVersion`/`targetSdkVersion` must
   match Capacitor v8 requirements.
7. Google Play Families policy: rewarded ads require the Data Safety form and
   the AdMob "families" flag if the game ships as child-directed.

## 4. Required iOS configuration (when the shell is added)

1. `npx cap add ios && npx cap sync`
2. `Info.plist`: `NSUserTrackingUsageDescription` only if ATT is adopted;
   AdMob will otherwise serve limited ads (acceptable for the placeholder
   build).
3. App Transport Security: all outgoing requests are HTTPS (AdMob is).
4. Signing via Xcode; the rewarded-video delegate is already abstracted in
   `ads.ts`.

## 5. What is intentionally NOT done in this phase

- No `npx cap add android` / `cap add ios` (no native folders committed).
- No production AdMob ids (test ids remain; production placeholders exist).
- No store assets, signing, or upload.
- No replacement of any working web functionality — the browser build stays
  the source of truth and the native shell would simply wrap `dist/`.
